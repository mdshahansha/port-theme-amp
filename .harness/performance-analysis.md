# Passive performance discovery

No Core Web Vitals, network waterfall, CPU trace, frame-rate measurement, layout-shift score, or compositing measurement was available. Browser `performance` was undefined in the read-only scope; no synthetic scores or baseline estimates are reported. Host, network, cache conditions, and renderer/browser version are unknown.

Observed: the homepage can render large visible media and custom fonts; three font-preload links exist; episode, Puck, and news image nodes use loading=lazy; videos reach readyState 4 after interaction/scroll. HOME-CSSOM-001 confirms font-face mapping, woff2/woff2-variations formats, and font-display swap; the actual requested subset/load status remains unknown. Hero words use CSS keyframes; Pucks and marquees have long-running CSS loops. Blur at 28/40px and grain cover large hero areas. The DOM includes numerous shared immutable CSS paths and Svelte class indicators. Those facts do not prove efficient hydration, automatic image optimization, low main-thread work, or GPU compositing.

Declared CSS alternatives in HOME-CSSOM-001 disable or replace several animations under reduced motion, hide decorative drifters/duplicate marquee groups, and enable horizontal overflow without the marquee mask. Hover CSS pauses proof groups; `.ot-mini` focus-visible CSS disables animation/mask and removes duplicates while enabling horizontal overflow. Runtime preference/hover/focus behavior and the performance effect of these rules were not measured. See [CSS declaration findings](evidence/observations/cssom-findings.md).

Loading sample: the Orb hero video showed a native loading spinner at initial inspection. The first Chronicle measurement had no H1 and document height 900px; the later DOM included actual content. This is a transient retrieval/rendering observation, not a timed loading benchmark or website error. Some early full-page thumbnails initially looked blank, then their natural dimensions resolved. This is consistent with lazy loading, but no exact threshold was measured.

Risks (inferred): font-metric substitution may shift hero, table, and article wraps; long dual-stream media plus other demo videos can consume network/decoding resources; continuous marquees/Pucks and large blur surfaces can stress mobile devices; invisible phrase copies and large hidden transcript DOM increase work; accumulated media/sidebar height changes complicate visual comparison. Actual impact remains unmeasured.

Recommendations: measure cold/warm loading under declared conditions; record font readiness, media state, LCP element, CLS, long tasks, and frames; instrument the visibility lifecycle to avoid unnecessary offscreen work after confirming reference behavior; validate paired videos at multiple times; preserve layout reservation; use approved assets with dimension metadata. Any performance budget must be agreed in the implementation task and clearly labeled as a proposed requirement, not an Amp baseline.
