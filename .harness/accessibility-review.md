# Accessibility observations and open risks

This is a selective inspection, not a conformance audit. Evidence: HOME-STRUCT/CSS, HOME-CSSOM-001, INT-MENU/POPOVER/VIDEO/DOCS, INT-INSTALL-COPY-002, RESP-MATRIX. No assistive-technology session or automated accessibility scanner was run.

Confirmed: the homepage uses one dynamic H1 and section headings. Its rotating title has a current sr-only phrase and aria-hidden visual/measurement layers. Marketing navigation and footer use links; features and news use whole-card anchors. Docs has banner, main, article, and navigation semantics and one sans-serif H1. Popover triggers expose expanded state: the orb is a button, while the full-width explanatory anchor has button role and no href. Pricing uses tab roles/selected state and FAQ expanded state. Player caption/sidebar controls are DOM buttons with aria-pressed; the native accessibility snapshot presents them as checkboxes. A replacement must choose consistent semantics rather than blindly copying the mismatch.

Tested keyboard behavior: Escape closes hero popovers and the mobile menu. Tab from an open menu reaches Home with a foreground 1px ring via shadow. Escape dismissal works for the mobile docs drawer/search; search initially focuses a combobox/listbox. Desktop feature classes declare a 2px primary focus outline with negative offset; this was not independently verified with the keyboard. The native installer select has an accessible Install platform label. The mobile menu target is 48 × 48px; many desktop navigation links are 30px high and the hero CTA is 38px high, so do not claim a universal 44px target minimum.

Potential risks requiring evidence: dynamic sr-only text may be announced undesirably; duplicate testimonial groups may repeat in keyboard/screen-reader order; compact moving cards have no verified explicit pause control; full focus containment, scroll lock, and focus restoration in the mobile overlay are not established; the expanded menu state persists on resize while the menu is hidden on desktop; some copy icons lack an observed label; many metadata/background images have empty alt text. Meaningful images must be assessed individually. Headings in hidden wrappers and player transcripts must not be counted as visible hierarchy solely from textContent.

Reduced-motion **CSS handling is confirmed; runtime behavior is UNKNOWN**. HOME-CSSOM-001 declares no title entrance/emphasis animation and hides the exit word; replaces storm motion with fade-only animation names; hides testimonial drifters and disables their animations; disables marquee-group animation, hides duplicates, removes the mask, enables horizontal overflow, and sets right padding to 0; disables caret animation. Hover CSS pauses proof groups. Focus-visible CSS on `.ot-mini` removes duplicates, animation, and mask and enables horizontal overflow. These declarations were inspected, but runtime reduced-motion, hover, and focus states were not exercised.

The measured reduced-motion preference was false; the available viewport API provides dimensions only. A dark preference did not change cream marketing pages. Contrast ratios were not measured for all token/opacity combinations; do not declare WCAG compliance based on the palette alone. Exact browser zoom, high DPR, and keyboard-fullscreen behavior remain unverified.

INT-INSTALL-COPY-002 confirms that clicking the visible Windows command at 1440px exposes a Copied to clipboard toast heading, Dismiss button, and changed adjacent icon node. Announcement semantics, focus behavior, and toast timing remain unverified. The later clipboard accessor returned earlier docs source, so command payload success and the tool-versus-site cause remain UNKNOWN; visible feedback alone does not verify the copied content.

Future acceptance: verify full keyboard cycles, Enter/Space semantics, focus visibility and return, drawer/trap/dismissal behavior, screen-reader current-title/player labels, hiding of duplicate decorative data, caption accessibility, touch-target sizing, contrast, and the actual reduced-motion preference. These are recommendations; reconstruction should reproduce essential behavior while correcting approved accessibility risks, without silently claiming that the reference already meets them.
